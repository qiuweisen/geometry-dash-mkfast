# SEO Audit: play-geometry-dash.com

审计范围：当前工作区代码、已部署站点首页/robots/sitemap，以及 Geometry Dash Lite 游戏页。审计日期：2026-09-23。

## 结论

基础可抓取性已经成立，但站点还处于“模板已上线、单游戏 SEO 尚未验证”的阶段。第一阶段目标不是扩充游戏数量，而是用 Geometry Dash Lite 验证曝光、点击和游玩行为；SEO 内容层与 iframe 游戏运行层必须保持独立。

## 已验证通过

- `https://play-geometry-dash.com/` 返回 200。
- `https://play-geometry-dash.com/game/geometry-dash-lite` 返回 200。
- `/` 作为默认英文 canonical，`/zh` 作为中文版本。
- robots.txt 可访问，并指向 `/sitemap.xml`。
- 游戏页存在 `VideoGame` JSON-LD、canonical、Open Graph 和语言 alternate。
- sitemap 包含首页、游戏页及中文对应页面。
- HTTPS、Cloudflare 缓存和 Worker 路由正常。

## 高优先级问题

### 1. Sitemap 包含不属于游戏站的模板页面

当前 sitemap 固定加入 `/blog`、`/showcases`、`/updates`、`/pricing`，并且线上还出现 `blog/what-is-xxx` 占位 URL。

影响：搜索引擎会发现与游戏主题无关或没有真实内容的页面，降低站点主题一致性，并产生薄内容/占位内容风险。

处理：只把已经有真实内容、明确允许索引的页面放进 sitemap。暂时没有内容的模板页面应从 sitemap 移除，并通过 `noindex` 或路由隐藏处理。

### 2. 模板内容仍会进入 HTML 和索引信号

`pages/index.json`、blog、showcases、pricing、landing 等文件仍包含 ShipAny、Gamiary、AI SaaS、`your-domain.com` 等内容。

影响：页面主题和品牌不一致，可能造成低质量或误导性搜索摘要。

处理：按页面清单逐项替换或关闭，不应只修改首页可见区。优先清理首页、footer、metadata、blog/showcases/pricing 的 title/description。

### 3. 首页内容目标仍不明确

首页目前同时承担“单个 Geometry Dash 落地页”和“游戏聚合首页”两种意图。游戏卡片结构可以保留，但首屏、SEO 文案和内部链接应明确是聚合站，并将 Geometry Dash Lite 作为 Featured Game。

处理：第一阶段采用 `SEO Landing Content + Game Entry + How to Play/FAQ` 结构。不要为了填充模板而新增游戏；确认搜索需求和流量后再扩展聚合内容。

## 中优先级问题

- 分类页是否有足够游戏和独特描述尚未确认；空分类页不应索引。
- 游戏页 description、封面和推荐游戏依赖数据库，新增游戏前需要保证每条记录都有独立 title、description、image、category 和 iframe URL。
- 首页 SEO 内容组件仍可能使用模板式“700+ games”等不真实表述，应改成基于实际数据的内容。
- 需要使用浏览器检查实际 JSON-LD、H1、图片 alt 和移动端布局；curl 无法完整验证客户端渲染结果。
- 站点尚未建立关键词到页面的映射，后续容易让首页、游戏页和分类页互相竞争。

## 页面规划

### 第一阶段：单游戏 SEO 验证

- `/`：Geometry Dash Lite 的 SEO 入口页，围绕 `geometry dash lite online` 和浏览器游玩意图。
- `/game/geometry-dash-lite`：主游戏详情页，关键词为 `geometry dash lite online`。
- `/how-to-play-geometry-dash-lite`：独立内容页，覆盖 controls、mobile、browser、troubleshooting 等长尾问题。
- `/about`、`/contact`、`/privacy-policy`、`/terms-of-service`：信任和合规页面；隐私/条款可以不进 sitemap，但不能返回 404。

### 第二阶段：有流量信号后

- 根据 Search Console 查询词、点击率和用户行为补充内容页。
- 只有单游戏验证出稳定流量后，才增加其他游戏或分类。
- iframe 页面与 SEO 内容页分开，通过明确内部链接连接。
- FAQ 只回答真实产品体验，不堆砌关键词。

### 暂不纳入索引

- 空分类页、管理页、登录/设置页、模板 blog/showcases/pricing 页面。
- 只有占位文本或没有独立价值的文章。

## 执行顺序

1. 清理 sitemap 中的占位和非游戏模板页面。
2. 清理首页、footer、metadata 和模板页面中的 ShipAny/Gamiary 残留。
3. 确认首页聚合结构和真实游戏数据模型。
4. 为单款游戏补齐独立 SEO 内容、FAQ、controls 和内部链接。
5. 用 Search Console 和分析数据验证曝光、点击和游玩行为。
6. 只有验证出流量后，再评估增加其他游戏。
